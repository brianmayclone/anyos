CSS Test 05: Display Property

Test 1: display: block

Expected: Block elements take the full width of their container. Each block element starts on a new line and stacks vertically. Even though the text is short, the background stretches the full container width.
display: block (1) -- full width
display: block (2) -- full width
display: block (3) -- full width

Test 2: display: inline

Expected: Inline elements flow with surrounding text on the same line. They only take as much width as their content. Width and height properties are IGNORED on inline elements. The boxes should appear side by side on one line (wrapping only if the line runs out of space).

Text before inline (1) inline (2) inline (3) text after.

Note: width/height on inline elements should have no effect:

inline with width:300px height:100px (IGNORED)

Test 3: display: inline-block

Expected: Inline-block elements flow inline (side by side) like inline elements, BUT they respect width and height. The first three boxes should appear on the same line (space permitting), each with their specified width and height.
inline-block
150x60
inline-block
120x80
inline-block
100x50

All three boxes should be on the same line, each respecting their width/height.

Test 4: display: none (Hidden Element)

Expected: Three boxes labeled 1, 2, 3. Box 2 has display: none, so it should be completely invisible and take up NO space. Box 1 and Box 3 should be adjacent with no gap where Box 2 would have been.
Box 1 (visible)
Box 2 (display: none -- SHOULD NOT BE VISIBLE)
Box 3 (visible, should be immediately after Box 1)

Test 5: Overriding Default Display Types

Expected: A span (normally inline) forced to display: block -- should take full width and start on its own line. A div (normally block) forced to display: inline -- should flow inline with text and not take full width.

span elements made block:

span with display: block (takes full width) another span with display: block

div elements made inline:

Text before

div display: inline
another div display: inline
text after.

Test 6: Width/Height Behavior per Display Type

Expected: Block with width:200px height:60px -- the box should be 200px wide and 60px tall. Inline with width:200px height:60px -- width and height should be IGNORED (box wraps its content). Inline-block with width:200px height:60px -- the box should be 200px wide and 60px tall, but flow inline.

All three have: width: 200px; height: 60px

block (200x60 works)
inline (200x60 ignored)

inline-block (200x60 works)

Test 7: Margin and Padding Behavior by Display Type

Expected: Block element: all margin and padding apply normally. Inline element: horizontal margin/padding work, but vertical margin has NO effect and vertical padding does not push surrounding content (it may bleed visually). Inline-block: all margin and padding work normally.

All have: margin: 20px; padding: 15px

block: margin and padding fully respected
Text before inline: vertical margin ignored text after (notice vertical padding may overlap)
Text before inline-block: all margin/padding work text after

Test 8: Navigation Bar with Inline-Block

Expected: A simulated navigation bar using inline-block elements. All items should appear in a horizontal row, each with consistent width and height, evenly spaced. This demonstrates the common use case of inline-block for horizontal layouts.
