CSS Test 34: Min/Max Width and Height

Test 1: min-width Preventing Shrinking

Expected: Both boxes have width:10%, but the first box has min-width:200px. The first box should be AT LEAST 200px wide even if 10% of the container is less than 200px. The second box (no min-width) may be very narrow. Resize the window: the first box stops shrinking at 200px.
width: 10%, min-width: 200px - will NOT shrink below 200px
width: 10%, no min-width - can become very narrow
The teal box stays >= 200px wide. The red box follows the 10% width exactly.

Test 2: max-width Preventing Growing

Expected: Both boxes have width:100%, but the first box has max-width:400px. The first box should grow to at most 400px even if 100% of the container is wider. The second box (no max-width) stretches to full container width. Resize: the first box stops growing at 400px.
width: 100%, max-width: 400px - will NOT grow beyond 400px
width: 100%, no max-width - stretches to full container width
The teal box caps at 400px. The red box takes the full width.

Test 3: min-height Ensuring Minimum Height

Expected: Both boxes have the same text content. The first box has min-height:100px, so it should be at least 100px tall even though the text does not need that much space. The second box (no min-height) collapses to fit its text content exactly.
min-height: 100px - always at least 100px tall
No min-height - only as tall as needed for content
The teal box should be visibly taller than the red box, maintaining at least 100px height.

Test 5: min-width + max-width Combined (Responsive Clamping)

Expected: The teal box has width:50%, min-width:200px, max-width:500px. It will be 50% of the container but never narrower than 200px and never wider than 500px. The red box has only width:50% (no clamping). Resize the window: the teal box "clamps" between 200px and 500px while the red box freely follows 50%.
width: 50%, min-width: 200px, max-width: 500px (clamped range)
width: 50%, no min/max (unclamped - free to resize)
Resize the window. The teal box stays between 200px and 500px. The red box follows 50% exactly.

Test 6: Percentage-Based min/max Values

Expected: Inside a 60% width container: The teal box has width:20% but min-width:30% - it should render at 30% (the minimum overrides the smaller width). The golden box has width:100% but max-width:70% - it should render at 70% (the maximum caps the larger width). Percentages are relative to the parent container.
Container is 60% of test area width (dashed border)
width: 20%, min-width: 30% - min overrides, should be 30% of container
width: 100%, max-width: 70% - max caps, should be 70% of container

Test 7: max-width: 100% Responsive Image Pattern

Expected: Two "image" placeholders inside a 300px container. The first has max-width:100% and is 500px wide intrinsically - it should SHRINK to fit the 300px container (never exceeding container width). The second has no max-width restriction and is also 500px wide - it should OVERFLOW the container. The max-width:100% pattern is standard for responsive images.
Container: 300px wide
max-width: 100% (500px intrinsic, shrinks to fit 300px container)
Container: 300px wide (overflow visible)
No max-width (500px wide, OVERFLOWS the 300px container)
