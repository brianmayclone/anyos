Test 08: Form Elements

Test 8.1: Text and Password Inputs

Expected: Text input should show a single-line text box where characters are visible. Password input should mask characters (show dots or asterisks). Both should be editable and focusable.

Test 8.2: Placeholder Text

Expected: Placeholder text should appear in a lighter/grayed-out color inside empty inputs. When the user types, the placeholder should disappear. It should not be submitted as form data.

Test 8.3: Textarea

Expected: A multi-line text editing area. Should respect rows and cols attributes for sizing. Content should be editable, scrollable if overflowing, and preserve whitespace.




Test 8.4: Select, Option, Optgroup

Expected: A dropdown/select control. The selected option should be visible. Clicking should show all options. Optgroup should create labeled groups within the dropdown.

Test 8.5: Checkbox and Radio Button

Expected: Checkboxes should be square and allow multiple selections. Radio buttons should be circular and allow only one selection per name group. Both should be toggleable by clicking.

Test 8.6: Button Types

Expected: Each button type should render as a clickable element. submit/reset are input types, button element is more flexible. All should be visually distinct from text.

Test 8.7: Fieldset and Legend

Expected: Fieldset should draw a border around its content. Legend should appear as a label embedded in the top border of the fieldset. Content inside should be grouped visually.

Test 8.8: HTML5 Input Types

Expected: Each input type should render with appropriate browser-native UI (number spinner, date picker, color picker, range slider, etc.). Unsupported types should fall back to text input.

Test 8.9: Disabled Inputs

Expected: Disabled inputs should appear grayed out or visually muted. They should not be editable or clickable. The disabled state should be obvious to the user.


Test 8.10: Label Association (for attribute)

Expected: Clicking a label with a "for" attribute should focus or toggle the associated input. Labels wrapping inputs should also work. This tests accessibility and click target expansion.
