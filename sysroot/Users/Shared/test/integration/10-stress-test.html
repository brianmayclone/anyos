Conflicting Styles (Specificity)

Case 7
Expected: CSS specificity determines the winner. Inline styles beat ID selectors, which beat class selectors, which beat element selectors. Each line states what color it should be.

1. Class says red, no other rules. Should be: red

2. Class red + class blue (blue defined later in CSS). Should be: blue

3. ID says green, class says red. ID wins. Should be: green

4. Inline says yellow, ID says green, class says blue. Inline wins. Should be: yellow (#ffd93d)

5. No class, no ID, no inline color. Inherits from parent. Should be: default text color (#d4d4d8)

200 Sibling Div Elements

Case 14
Expected: 200 thin colored bars stacked vertically. Each bar is 4px tall with alternating colors. The browser should render all 200 without significant lag. Scrolling should be smooth.

Expected Rendering (Overall)

  • Case 1 (100 Nested Divs): A visible nesting pattern of bordered divs getting progressively smaller toward the center. The innermost div says "Depth 100". No stack overflow, no crash.
  • Case 2 (Long Word): Two boxes. The first (red border, overflow-wrap) shows the word breaking at the container edge across multiple lines. The second (yellow border, no overflow-wrap) may show the word overflowing the container horizontally.
  • Case 3 (Long Paragraph): A large paragraph (1000+ characters) that wraps naturally. All text should be visible. No truncation or clipping.
  • Case 4 (20x20 Table): A wide table with 20 columns and 20 rows. Cells contain "R1C1" through "R20C20". Table headers in teal. Alternating row backgrounds. Horizontal scroll if table exceeds container width.
  • Case 5 (50 List Items): Ordered list numbered 1-50 with descriptive text per item. All 50 items visible with proper numbering and indentation.
  • Case 6 (5-Level Nesting): Deeply nested unordered lists with increasing indentation per level. Items named by their hierarchy (e.g., "Level 3 - Item A.1.a"). All 5 levels visible.
  • Case 7 (Style Conflicts): Five lines testing CSS specificity. Line 1: red (class). Line 2: blue (later class wins). Line 3: green (ID beats class). Line 4: yellow (inline beats all). Line 5: default color (inherited).
  • Case 8 (Zero Dimensions): A red vertical line (zero width + border), a teal horizontal line (zero height + border), and three downward-pointing CSS triangles (zero width+height + border trick).
  • Case 9 (Empty Elements): Visible empty elements: bordered rectangles, colored rectangles, padding-only squares, and inline empties with visual properties. All should be visible despite having no text content.
  • Case 10 (Overlapping): Four semi-transparent colored boxes overlapping in a container. Box D (yellow, z-index:10) is on top. Box C (purple, no z-index) is between B and D. Boxes A and B at lower z-indices are partially obscured.
  • Case 11 (Floats): Left-floated blue box and right-floated purple box with text wrapping between them. The container expands to contain the floated elements via overflow:hidden.
  • Case 12 (DOM Stress): A button that generates 500 small colored squares in a flex-wrap container. Displays elapsed time. Should complete in under 500ms and not freeze the browser.
  • Case 13 (Inline Line Breaks): Highlighted span, bold, italic, and underlined text all wrapping across lines within a 400px container. Styling must persist across the line break.
  • Case 14 (200 Siblings): 200 thin horizontal bars (4px tall) stacked vertically with alternating colors. Every 10th bar is teal and thinner (2px). All 200 should render smoothly.
  • Overall: The page should load without crashes, freezes, or stack overflows. Each edge case is contained in its own section. Scrolling through the entire page should be smooth.
