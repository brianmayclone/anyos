Typography Showcase

A comprehensive demonstration of text rendering, formatting, and typographic elements. Every element on this page tests a different aspect of text layout and styling.

Body Text

Good typography is the foundation of readable web content. The body text you are reading now uses a 16px sans-serif font with 1.7 line-height, which provides comfortable spacing between lines. The text color is a slightly muted off-white (#c8c8d8) against the dark background, reducing eye strain while maintaining contrast.

A second paragraph demonstrates spacing between paragraphs. There should be a clear visual gap (margin-bottom: 16px) separating this paragraph from the one above. Consistent paragraph spacing is essential for readability, especially in long-form content like articles and documentation.

This third paragraph contains a much longer text block to test text reflow behavior. When a browser renders body text, it must correctly wrap words at the right edge of the container, maintaining consistent line spacing and avoiding orphaned words where possible. The text column width (max-width: 800px) keeps lines at a comfortable reading length of approximately 70-80 characters per line, which research suggests is optimal for on-screen reading comprehension and speed.

Inline Formatting

This paragraph contains bold text created with the strong element, italic text with the em element, and text that is both bold and italic using nested elements.

Here is an example of inline code using a monospace font with a colored background. You might see references to functions like document.getElementById() or CSS properties like display: flex in technical documentation.

Links can appear inline within text and should be visually distinct (teal color). Visited links, like this one, may appear differently in some browsers. Underlined text should be used sparingly as it can be confused with links. Strikethrough text indicates deleted or outdated information.

Keyboard shortcuts are shown with Ctrl + C to copy and Ctrl + V to paste. The kbd element provides a distinct visual style.

You can highlight important text using the mark element. This draws attention to key phrases within a larger body of text, like marking search results on a page.

The HTML abbreviation element provides a dotted underline and tooltip for acronyms. Hover over CSS to see the full title.

Scientific notation uses superscript: E = mc2, and chemical formulas use subscript: H2O. These should position correctly relative to the baseline.

Code Blocks

A code block with syntax-like token coloring:

/// Renders a styled button component.
/// Returns the computed dimensions after layout.
fn render_button(ctx: &mut RenderContext, label: &str) -> Rect {
    let padding = 8;
    let font_size = 14.0;
    let text_width = ctx.measure_text(label, font_size);

    ctx.fill_rect(
        ctx.x, ctx.y,
        text_width + padding * 2,
        font_size as i32 + padding * 2,
        0xFF4ECDC4, // teal background
    );
    ctx.draw_text(label, ctx.x + padding, ctx.y + padding, "sans-serif");

    Rect::new(ctx.x, ctx.y, text_width + padding * 2, 30)
}

Definition List

Serif
A typeface with small decorative strokes (serifs) at the ends of letterforms. Examples: Times New Roman, Georgia.
Sans-serif
A typeface without serifs, resulting in clean and modern letterforms. Examples: Arial, Helvetica, SF Pro.
Monospace
A typeface where every character occupies the same horizontal space. Used for code display. Examples: Courier, Andale Mono.

Text Alignment

text-align: left
This text is left-aligned, which is the default alignment for left-to-right languages. Each line starts at the left margin and the right edge is ragged.
text-align: center
This text is center-aligned. Each line is horizontally centered within the container. Common for headings and hero text.
text-align: right
This text is right-aligned. Each line is flush with the right margin and ragged on the left. Used in certain UI patterns.
text-align: justify
This text is justified. Both left and right edges are flush, achieved by adjusting word spacing. Justified text works better with longer lines and can create uneven spacing in narrow columns.

Expected Rendering

  • Body text: Three paragraphs of readable text at 16px with 1.7 line-height. Clear spacing between paragraphs. Text wraps naturally at container edges (~800px wide).
  • Headings: Six heading levels forming a clear visual hierarchy. h1 (36px) through h6 (14px uppercase). Each followed by a descriptive paragraph in smaller muted text. Headings are progressively smaller and lighter.
  • Inline formatting: Bold, italic, inline code (yellow on dark blue pill), keyboard keys (bordered monospace), highlighted text (yellow tint), abbreviations (dotted underline), superscript/subscript, underline, and strikethrough all visible in the same paragraphs.
  • Blockquotes: Indented blocks with teal left border, darker background. Italic text with citation below. The nested blockquote has a purple left border and is further indented within the outer quote.
  • Code blocks: Dark background pre elements with monospace text. Colored syntax tokens: red keywords, teal functions/types, yellow strings, gray comments, purple numbers. Code should be horizontally scrollable if wider than container.
  • Lists: Unordered list with disc bullets and nested items at increasing indentation (3 levels deep). Ordered list with numbers and nested ordered sub-list. Definition list with bold terms and indented descriptions.
  • Text alignment: Four boxes demonstrating left, center, right, and justified alignment. Each labeled with its alignment value. Justified text should have even left and right edges.
  • Small print: Noticeably smaller text (12px) compared to body text. Caption text is small and italic. Horizontal rule renders as a thin line.
  • Mixed content: Final paragraph contains bold, italic, code, links, highlights, keyboard shortcuts, superscript, subscript, abbreviations, strikethrough, and small text all within a single paragraph. All should render correctly without layout breaks.
